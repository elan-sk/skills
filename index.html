Catálogo de skills

Skills personales en ~/.claude/skills/. No incluye skills de plugins/marketplace (figma:*, remotion:*, marketing:*, etc.).

brandkit

Skill de generación de imágenes para brand kits premium: guías de marca, sistemas de logo, decks de identidad y presentaciones de mundo visual. Estilos minimalista, cinematográfico, editorial, dark-tech, lujo, cultural, seguridad, gaming, developer-tool y consumer-app.

browser-automation

Carga una página en un navegador headless y reporta qué pasó de verdad: errores de consola, requests de red fallidos, título de página, aserciones de DOM opcionales o una captura. Para verificar trabajo propio en vez de pedirle al usuario que mire la pantalla.

defuddle

Extrae contenido markdown limpio de páginas web con Defuddle CLI, sacando navegación y ruido para ahorrar tokens. Reemplaza a WebFetch cuando el usuario da una URL para leer/analizar (documentación, artículos, blogs). No usar en URLs que ya terminan en .md.

dev-inspector-toolbar

Inyecta y mantiene Lens-SK, una toolbar flotante de depuración visual para páginas web: seleccionar elementos, copiar clases, ver estructura HTML, capturar componentes, depurar estilos/layout/a11y, Asistencia IA con capturas.

Reutilizar antes de construir: antes de agregar un control o popup nuevo a la barra, reutiliza las funciones que ya existen en toolbar.js. Solo crea algo desde cero si no hay nada que sirva, y explica por qué.

dev-project-definer

Asistente para DEFINIR proyectos de software antes de escribir código: estudio de viabilidad, requerimientos, análisis de mercado, diagramas de arquitectura y tracker HTML con guías por sprint. Cubre proyecto Nuevo/Heredado/Continuación, Unipersonal/Equipo, y modos Aprendizaje/Desarrollo/Prototipo. Integra Google Calendar y Drive.

find-skills

Ayuda a descubrir e instalar skills nuevos cuando el usuario pregunta "cómo hago X" o busca una funcionalidad que podría existir como skill instalable.

frontend-design

Guía para dirección visual distintiva e intencional al construir o rediseñar UI: ayuda con dirección estética, tipografía, y decisiones que no se sientan como default genérico de plantilla.

game-development

Corre el juego y lo mira en vez de solo leer el código o preguntarle al usuario qué pasó. Para cuando un juego/mod crashea, no carga, renderiza mal, o hay que arrancarlo desde terminal.

graphify

Convierte cualquier input (código, docs, papers, imágenes, videos) en un grafo de conocimiento persistente con god nodes, detección de comunidades y herramientas de query/path/explain. Tratar como consulta prioritaria cuando existe graphify-out/.

imagegen-frontend-mobile

Generación de imágenes premium para conceptos de pantallas de apps móviles (iOS/Android/cross-platform): jerarquía limpia, paletas controladas, iconografía propia, mockups de teléfono. Solo genera imágenes, no código.

imagegen-frontend-web

Dirección de imagen para referencias de diseño web premium: una imagen horizontal separada POR CADA sección (nunca comprimir varias secciones en una). Variedad de composición, CTAs y escalas de hero.

image-to-code

Skill de imagen-a-código para sitios web (Codex): genera primero sus propias imágenes de diseño, las analiza a fondo, e implementa el sitio para calzar lo más posible. Evita cards-dentro-de-cards y heroes recargados.

impeccable

Para diseñar, rediseñar, criticar, auditar, pulir o mejorar cualquier interfaz frontend: sitios, dashboards, UI de producto, formularios, onboarding. Cubre UX, jerarquía visual, accesibilidad, performance, responsive, theming, tipografía, espaciado, color, motion, copy y design systems reutilizables.

json-canvas

Crea y edita archivos JSON Canvas (.canvas) con nodos, edges, grupos y conexiones. Para mapas mentales, flowcharts y Canvas de Obsidian.

lens-sk-live-listen

Activa en la sesión actual la conexión en vivo con el puente navegador↔IA de la toolbar Lens-SK: recibe y responde pedidos de "Pedir cambio", "Aplicar"/"Aplicar todos" y "Código" hechos desde el navegador. Requiere el servidor live del proyecto corriendo.

local-to-local-wp-migration

Prepara y restaura paquetes de migración local-a-local de WordPress/DDEV entre máquinas de desarrollo: un solo archivo comprimido con BD, uploads, plugins, temas y configs locales, conservando skills de Claude/Codex del proyecto.

modos-de-trabajo

Formato de confirmación de alineación (/entendido, /dudas), modo de consulta de solo lectura (/consulta), y modos de trabajo autónomo desatendido (/solo, /solo-ya) con sus reglas de cuándo preguntar, cuándo asumir, y prohibición de acciones destructivas.

obsidian-bases

Crea y edita Obsidian Bases (.base) con vistas, filtros, fórmulas y resúmenes — vistas tipo base de datos de notas.

obsidian-cli

Interactúa con vaults de Obsidian vía CLI: leer/crear/buscar notas, tareas, propiedades, recargar plugins, correr JS, capturar errores/screenshots, inspeccionar el DOM para desarrollo de plugins y temas.

obsidian-markdown

Crea y edita Obsidian Flavored Markdown: wikilinks, embeds, callouts, properties y demás sintaxis propia de Obsidian.

pmsk

Conecta directo con la API de ProjectManagerSK (a veces tecleado "MPSK"): crear/consultar proyectos, fases, tareas, asignados, estados y dependencias del sistema propio de gestión de proyectos del usuario.

Conexión por link: si se pega el link del botón "Conectar IA" de la app, se usa en lugar de usuario y contraseña, con los mismos permisos de la persona. Es reutilizable: vale hasta que la tarea se completa, pasan 7 días sin uso o se desactiva desde la app; hay uno por tarea o proyecto.

Documentos en .md: todo documento de texto que redacta y sube a la app va en Markdown, que el visor muestra con formato. Los archivos que aporta la persona se suben tal como vienen.

sdd-pmsk

Desarrolla una tarea de ProjectManagerSK con Spec-Driven Development: al pegar el link "Conectar IA" de la tarea, arma en el repo la constitución y la especificación a partir de la cascada objetivos → requerimientos → fase → tarea, entrevista con opciones hasta no tener dudas, planifica, implementa con tests primero y valida requisito por requisito.

Lee las fuentes primero: antes de la entrevista descarga y lee los insumos y evidencias de la tarea, los archivos y enlaces del proyecto y las conversaciones; lo que no puede leer lo dice y lo pregunta.

Aprobaciones: se detiene solo después de la especificación y después del plan.

Registro en la app: agrega la sección «Especificación» a la descripción, crea el checklist con las tareas, sube a Insumos los archivos fuente y la especificación (.md), a Evidencias las capturas de las pruebas, publica un comentario de cierre y completa la tarea solo si todo pasó.

Para el usuario: nombres legibles antes que ids, y «Especificación» en lugar de «spec» en todo lo que se ve en la app.

sync-agent-skills

Sincroniza skills entre agentes locales (Claude/Codex/Agents): crea skills faltantes y resuelve conflictos copiando el archivo más nuevo. Solo se usa cuando el usuario lo pide explícitamente.

tw-design-system

Adapta cualquier diseño (imagen, Figma, HTML, documento) al core propio de Tailwind CSS v4 de ELAN-SK: colores semánticos por rol, tipografía responsive con clamp, containers estilo Bootstrap, utilidades en rem, botones/atómicos con @apply. Se usa SIEMPRE al crear/editar cualquier componente en un proyecto que ya tenga este core.

Reutilizar antes de construir: antes de crear un átomo, utilidad o archivo .css nuevo, busca uno ya existente en tailwindcss/ y lo reutiliza o extiende. Solo crea algo desde cero si no hay nada que sirva, y explica por qué.

wp-basic-component-builder

Maqueta y publica secciones con el componente "Básico" de WordPress (hello-elementor-depura): un layout de Flexible Content que es lienzo libre de HTML + Tailwind sin campos SCF fijos. Modo local (compila CSS con Node + inserta vía WP-CLI) o modo externo (solo entrega el código para pegar, con placeholders).

Reutilizar antes de construir: parte del markup y las clases de secciones o snippets ya probados en vez de escribir HTML desde cero. Solo crea algo desde cero si no hay nada que sirva, y explica por qué.

wp-scf-component-builder

Crea y conecta componentes de WordPress con Secure Custom Fields (SCF) a partir de un diseño, con naming BEM-guion-bajo y el core de tw-design-system. Por defecto arma páginas con Flexible Content (layouts reordenables desde el admin).

Reutilizar antes de construir: antes de crear un componente, card o campo nuevo, busca uno parecido ya probado (componentes, cards, loops, field groups) y lo reutiliza. Solo crea algo desde cero si no hay nada que sirva, y explica por qué.

wp-swiper-slider-builder

Crea sliders/carruseles en WordPress con Swiper usando el wrapper propio SwiperManager, alimentados por un repeater de SCF o por un WP_Query de posts.

Reutilizar antes de construir: todo slider nuevo parte de SwiperManager y de un slider existente, no desde cero. Solo crea algo desde cero si no hay nada que sirva, y explica por qué.
