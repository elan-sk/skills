¿Qué es Tauri y por qué lo usamos?

Lunes

El problema que Tauri resuelve — y por qué React solo no alcanza

6–8 pm · 2h ▼
💡
Contexto: ¿por qué no publicar PrecioJusto como una web normal? Una app web no puede acceder a la base de datos local del usuario, no puede guardar archivos en el sistema operativo, y requiere conexión a internet. PrecioJusto necesita todo eso — por eso necesitamos convertirla en una aplicación de escritorio nativa.

Cuando quieres crear una app de escritorio con tecnología web (React, TypeScript, HTML/CSS), tienes básicamente dos opciones grandes: Electron o Tauri. Entender la diferencia te ayudará a apreciar por qué elegimos Tauri para PrecioJusto.

Electron — el enfoque tradicional

Electron es la tecnología que usa VS Code, Slack, WhatsApp Desktop y Discord. Funciona así: incluye un navegador Chrome completo + Node.js dentro de cada app. Eso significa que cada app Electron lleva su propio navegador empaquetado.

Característica Electron Tauri 2.0
Tamaño del instalador 80–200 MB 3–10 MB
Uso de RAM al iniciar ~200 MB mínimo ~30 MB
Lenguaje backend Node.js (JavaScript) Rust (compilado, nativo)
Motor de renderizado Chromium incluido en el .exe WebView del sistema (Edge en Windows)
Velocidad de arranque Lento (carga Chromium) Rápido (WebView ya existe)
Curva de aprendizaje Fácil (todo JS) Medio (Rust es nuevo)

¿Cómo funciona Tauri internamente?

Tauri tiene dos partes que trabajan juntas:

┌────────────────────────────────────────────────┐
│ FRONTEND (lo que el usuario VE) │
│ Tu código React + TypeScript + TailwindCSS │
│ Corre dentro del WebView de Windows (Edge) │
│ │
│ ✓ Formularios, botones, pantallas │
│ ✓ Zustand para estado de la app │
│ ✗ NO puede acceder a archivos del sistema │
│ ✗ NO puede hablar con SQLite directamente │
└───────────────────┬────────────────────────────┘
│
invoke("guardar_insumo", datos)
│
┌───────────────────▼────────────────────────────┐
│ BACKEND (lo que el usuario NO VE) │
│ Código Rust (src-tauri/) │
│ Compilado a código nativo — ultra rápido │
│ │
│ ✓ Lee y escribe en SQLite │
│ ✓ Accede al sistema de archivos │
│ ✓ Controla la ventana nativa │
│ ✓ Accede a recursos del sistema operativo │
└────────────────────────────────────────────────┘
🎯
¿Cómo aplica esto a PrecioJusto? Cuando el usuario haga clic en "Guardar insumo", React captura los datos del formulario → llama a Rust con invoke() → Rust los escribe en SQLite → responde "OK" → React actualiza la pantalla. El usuario no sabe que Rust existe, pero él hace el trabajo pesado.

¿Qué es Rust (en términos simples)?

Rust es un lenguaje de programación creado por Mozilla, similar a C++ pero sin los errores de memoria que hacen tan problemático a C++. Es extremadamente rápido — comparable al código compilado de C — y es usado por empresas como Mozilla, Discord, Cloudflare y Microsoft para partes críticas de su infraestructura.

⚠️
No necesitas aprender Rust a fondo ahora Para esta semana y las próximas, Tauri genera la estructura base de Rust automáticamente. Solo vas a leer el código, entender qué hace, y hacer ajustes pequeños siguiendo los ejemplos de la documentación. El aprendizaje de Rust será gradual y orgánico.

Tauri Commands — el puente entre React y Rust

Lee tauri.app/develop/calling-rust — Cómo JavaScript llama funciones del backend

Martes

invoke() — cómo React habla con Rust

6–8 pm · 2h ▼
🌉
El concepto más importante de Tauri invoke() es la función que te permite llamar código Rust desde React. Es el puente entre el frontend y el backend. Cada vez que necesites acceder a la base de datos, a archivos, o a recursos del sistema, usarás invoke().

¿Cómo funciona un Command?

Un "Command" en Tauri es simplemente una función Rust que tiene el atributo #[tauri::command] y está registrada en el Builder. Una vez registrada, React puede llamarla por nombre con invoke().

Parte 1 — Defines el command en Rust (src-tauri/src/lib.rs):

// El atributo #[tauri::command] hace que esta función sea accesible desde React
#[tauri::command]
fn saludar(nombre: String) -> String {
    format!("¡Hola, {}! Desde el backend Rust.", nombre)
}

// Aquí registras todos tus commands para que Tauri los conozca
pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![saludar])  // ← registrar
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}Rust

Parte 2 — Lo llamas desde React (src/components/MiComponente.tsx):

import { invoke } from "@tauri-apps/api/core";

async function probarSaludo() {
    // El primer argumento es el nombre del command (en snake_case)
    // El segundo es un objeto con los argumentos que espera Rust
    const respuesta = await invoke<string>("saludar", { nombre: "ELAN" });
    
    console.log(respuesta);
    // → "¡Hola, ELAN! Desde el backend Rust."
}
TypeScript
✨
Nota el await invoke() siempre retorna una Promise — es como hacer un fetch() a una API, pero en lugar de internet, la petición va al backend Rust local. La respuesta puede ser casi inmediata (microsegundos), pero la sintaxis asíncrona es la misma.

Cómo aplica esto a PrecioJusto

Cuando termines el Sprint 2, tus commands reales se verán así:

// En Rust — guardar un insumo en SQLite
#[tauri::command]
async fn crear_insumo(db: State<DbState>, nombre: String, precio: f64) -> Result<i64, String> {
    // Aquí Rust habla con SQLite y devuelve el id del nuevo insumo
    Ok(insertar_en_db(&db, nombre, precio).await?)
}Rust
// En React — formulario de nuevo insumo
const handleGuardar = async () => {
    const nuevoId = await invoke<number>("crear_insumo", {
        nombre: formData.nombre,
        precio: formData.precio
    });
    console.log(`Insumo guardado con id: ${nuevoId}`);
};TypeScript

SQL básico — el lenguaje de las bases de datos

Recurso: sqlitetutorial.net — Estudia SELECT, INSERT, UPDATE y DELETE

📦
¿Qué es SQLite y por qué es perfecta para PrecioJusto? SQLite es una base de datos que vive en un solo archivo .db en el computador del usuario. No necesita instalar un servidor de base de datos (como MySQL o PostgreSQL). Es la base de datos más usada del mundo — Android, iOS, navegadores web, y miles de apps de escritorio la usan. Ideal para apps de un solo usuario como PrecioJusto.
Miércoles

SELECT — Consultar datos de la base de datos

6–8 pm · 2h ▼

SELECT es el comando más usado en SQL. Lo usarás para leer datos. En PrecioJusto, cada vez que cargues una lista de insumos, servicios o cotizaciones, usarás SELECT.

Sintaxis básica

-- Obtener TODOS los inputs (insumos)
SELECT * FROM inputs; -- inputs = insumos

-- El * significa "todas las columnas"
-- FROM dice de qué tabla leerSQL
-- Obtener solo columnas específicas
SELECT name, price, unit_name -- name = nombre, price = precio, unit_name = unidad
FROM inputs; -- inputs = insumos

-- Obtener inputs filtrados por condición
SELECT name, price -- name = nombre, price = precio
FROM inputs -- inputs = insumos
WHERE price > 1000; -- filtrar insumos que cuesten más de 1000

-- Ordenar resultados
SELECT name, price -- name = nombre, price = precio
FROM inputs -- inputs = insumos
ORDER BY name ASC;SQL
🎯
En PrecioJusto usarás SELECT para: Cargar la lista de insumos al abrir la pantalla. Buscar insumos por nombre. Cargar el historial de cotizaciones. Obtener la configuración de la app (moneda, idioma). Casi todo lo que el usuario "ve" viene de un SELECT.
Palabras clave SQL de hoy
SELECTQué columnas quiero ver (o * para todas)
FROMDe qué tabla leer los datos
WHERECondición de filtro (como un if en JavaScript)
ORDER BYOrdenar los resultados por una columna
Jueves

INSERT y UPDATE — Crear y modificar datos

6–8 pm · 2h ▼

INSERT crea registros nuevos. UPDATE modifica registros existentes. Son los comandos que usarás cuando el usuario llene un formulario y haga clic en "Guardar".

INSERT — Crear un registro nuevo

-- Crear un nuevo input (insumo)
INSERT INTO inputs (name, price, unit_name) -- inputs = insumos; name = nombre, price = precio, unit_name = unidad
VALUES ('Harina de trigo', 2500.00, 'kg');

-- No incluyes el 'id' — SQLite lo genera automáticamente (AUTOINCREMENT)
-- Después de este INSERT, puedes obtener el id generado con: last_insert_rowid()SQL
-- Crear un service (servicio) con todos sus campos
INSERT INTO services (name, details, price, price_type) -- services = servicios; name = nombre, details = descripcion, price = costo_mensual, price_type = tipo
VALUES ('Arriendo bodega', 'Almacenamiento mensual', 500000, 'static');

-- Timestamp automático con la función datetime()
INSERT INTO inputs (name, price, created_at) -- inputs = insumos; name = nombre, price = precio
VALUES ('Azúcar', 3200, datetime('now'));SQL

UPDATE — Modificar un registro existente

-- Actualizar el precio de un input (insumo) específico
UPDATE inputs -- inputs = insumos
SET price = 2800 -- price = precio
WHERE id = 1;

-- ⚠️ SIEMPRE usa WHERE en un UPDATE
-- Sin WHERE, actualizarías TODOS los registros de la tablaSQL
-- Actualizar varios campos a la vez
UPDATE inputs -- inputs = insumos
SET
    price = 2800,         -- price = precio
    unit_name = '500g',  -- unit_name = unidad
    updated_at = datetime('now')
WHERE id = 1;SQL
🚨
La regla más importante del UPDATE (y DELETE) Siempre, siempre, siempre incluye el WHERE. Un UPDATE inputs SET price = 0 sin WHERE pondría en cero el precio de TODOS los inputs (insumos) de la base de datos. Esto es difícil de deshacer.
Viernes

DELETE — Eliminar registros (con cuidado)

6–8 pm · 2h ▼

DELETE elimina registros de forma permanente. En PrecioJusto usamos borrado definitivo — cuando el usuario elimina un insumo o servicio, la fila desaparece de la base de datos.

DELETE — el patrón que usaremos en PrecioJusto

-- Eliminar un input (insumo) específico por su id
DELETE FROM inputs -- inputs = insumos
WHERE id = 5;

-- ⚠️ Igual que UPDATE: SIEMPRE usa WHERE
-- DELETE FROM inputs; — eliminaría TODA la tablaSQL
💡
Resumen del CRUD en SQL Create → INSERT INTO  ·  Read → SELECT FROM  ·  Update → UPDATE SET  ·  Delete → DELETE FROM

🦀
¿Por qué necesitas instalar Rust? Tauri usa Rust para el backend de la app. Cuando ejecutas npm run tauri dev o npm run tauri build, en realidad está compilando código Rust. Sin Rust instalado, el comando falla.

Instalar el plugin SQL de Tauri

⏱ ~20 min ▼
🔌
¿Qué es un plugin en Tauri? Los plugins de Tauri extienden las capacidades de la app. El plugin SQL agrega la capacidad de conectarse a bases de datos SQLite (o MySQL/PostgreSQL). Sin él, tu código React no puede hablar con SQLite.
  • 1

    Instalar el paquete JavaScript del plugin

    npm install @tauri-apps/plugin-sql

# Este paquete exporta las funciones que usarás en React
# para conectarte a SQLite (Database.load(), db.execute(), db.select())Terminal
  • 2

    Agregar la dependencia Rust en Cargo.toml

    Abre src-tauri/Cargo.toml y agrega la línea del plugin en la sección [dependencies]:

    [package]
name = "precio-justo"
version = "0.1.0"
edition = "2021"

[dependencies]
tauri = { version = "2", features = [] }
tauri-plugin-sql = { version = "2", features = ["sqlite"] }  # ← NUEVO

[profile.release]
panic = "abort"
codegen-units = 1
lto = true
opt-level = "s"
strip = trueTOML
    ⚠️
    TOML es sensible a la indentación y sintaxis A diferencia de JSON, TOML usa pares clave = valor y las secciones van entre corchetes como [dependencies]. No uses comillas dobles para las claves, solo para los valores de tipo string. Copia exactamente el formato que ves arriba.
  • 3

    Registrar el plugin en lib.rs

    Abre src-tauri/src/lib.rs — así debería verse después de agregar el plugin:

    // El pub fn run() es el punto de entrada de tu app Rust
pub fn run() {
    tauri::Builder::default()
        // Registrar el plugin SQL — añade esta línea
        .plugin(tauri_plugin_sql::Builder::default().build())
        // Aquí registrarás tus commands cuando los crees
        .invoke_handler(tauri::generate_handler![])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}Rust

Configurar los permisos de la app

⏱ ~15 min ▼
🔐
¿Por qué Tauri 2.0 tiene un sistema de permisos? Por seguridad. Tauri 2.0 implementó un modelo de "capabilities" (capacidades) — cada operación que la app puede hacer debe declararse explícitamente. Así, si alguien inyectara código malicioso en tu WebView, no podría hacer cosas que no están autorizadas. Es como los permisos de una app móvil.
  • 1

    Abrir el archivo de capabilities

    Abre src-tauri/capabilities/default.json. Debería existir desde que corriste npx tauri init.

  • 2

    Agregar los permisos SQL

    {
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capacidades principales de PrecioJusto",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "sql:allow-execute",   // ← INSERT, UPDATE, DELETE
    "sql:allow-select",    // ← SELECT (leer datos)
    "sql:allow-load"        // ← conectarse a la BD
  ]
}JSON
    ✅
    core:default incluye los permisos básicos de ventana (cerrar, minimizar, maximizar). Los permisos sql:* los provee el plugin que instalaste en el Paso 3.

  • !

    "MSVC not found" o errores de linker

    Tauri no puede conectarse al servidor de React porque no está corriendo. Asegúrate de que npm run dev esté activo en otra terminal, o usa simplemente npm run tauri dev que lo inicia automáticamente.

  • !

    Error de sintaxis en Cargo.toml o lib.rs

    TOML y Rust son muy estrictos con la sintaxis. Lee el error en la terminal — Rust da mensajes de error muy descriptivos con la línea exacta del problema y sugerencias de cómo arreglarlo.

  • !

    "Permission denied" en capabilities

    Revisa que el archivo default.json tiene los permisos sql:allow-execute, sql:allow-select y sql:allow-load exactamente como se muestra en el Paso 4.
